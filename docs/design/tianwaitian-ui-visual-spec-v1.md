# 天外天｜Android UI 视觉规范 v1.0（设计提案）

- 日期：2026-10-13
- 项目：`soozooq/gogogo`，现有源码主线 `main`
- 品牌方向：**天外天**（工作品牌名）；英文名尚未决定，不擅自新增
- 主视觉：**星座 / 连线 / 秩序 / 空间探索**，不再沿用 GPS 定位针作为品牌核心
- 目标：不破坏现有模拟能力的前提下，让 GoGoGo 从研发工具外观升级为易懂、统一的 Android 产品
- 本文件为**设计约束**，非已完成的代码实现，也不代表商标注册成功

## 1. 品牌 / 图标授权边界

已选参考素材：**SVG Repo — Constellation** https://www.svgrepo.com/svg/285388/constellation

- 2026-10-13 页面标注 `CC0 License`：允许自由复制、修改、商业使用且无需署名；引用 https://www.svgrepo.com/page/licensing
- `CC0` **不提供商标独占权**，不证明不存在第三方在先商标/其他权利。
- 现阶段素材为候选参考、**不直接替换启动图标**，保留来源 URL、许可证与确认日期。
- 上线前人工核查「天外天」第 9 类（下载软件）、适用的第 42 类（如软件服务）及图形近似；视运营范围决定其他类别。近似检索/注册核验不是自动化构建能保证的。
- 不声称自画图形就绝对可注册；不照搬他人品牌 Logo；新图应适配 48dp/72dp/108dp、Android adaptive icon 安全区与黑白/单色模式。
- 需要保存最终 SVG 原件、导出资源、许可凭据、作者和修改记录，方便维护。

## 2. 视觉性格

**关键词**：星空、清晰、从容、现代、微光、有层次。

- 星空元素**只用于**欢迎页、品牌块、少量 Hero/空状态。功能列表、日志、地图瓦片上绝不叠大面积星点。
- 操作控件以清晰的矩形/圆角卡片为主，**不用荧光描边和重发光**。
- 所有重要状态必须有文字，颜色不能成为唯一含义载体。
- 不将定位针/地球/罗盘等通用形状当主品牌，但功能图标仍可按语义使用。
- 保持白天和夜晚均可用，严禁只做深色截图。

## 4. 版式与组件

- 横向页面留白：16dp；窄屏 12dp；大屏可以扩至 24dp。
- 基础间距刻度：4 / 8 / 12 / 16 / 24 / 32dp，避免任意数值。
- 卡片圆角：16dp；主按钮：12dp；输入框：12dp；状态标签：8dp。
- 最小点击热区：48dp，按钮建议 48–52dp。
- 正文：14–16sp；次文 12–14sp；普通小标题 18sp；页面标题 24sp；只用系统字体。
- 经纬度使用 tabular numerals 或等宽格式显示；截断前要支持复制完整坐标。
- 动画：100–220ms 轻柔反馈；系统“移除动画/减少动态效果”时停用装饰性动效。
- 光效是可选小面积背景，不允许模糊大阴影损害地图帧率。
- 图标统一线宽和笔触；操作图标应有 contentDescription；纯装饰星点不进入无障碍阅读顺序。
- 高级工具必须可收起，不能丢失原功能入口。

## 5. 信息架构（理想五入口，渐进迁移）

**产品目标**：首页 / 地图 / 地点 / 诊断 / 设置。

现阶段不能直接一步替换底部导航，因为已有 `MainActivity`、`LabMapActivity`、`LabHubActivity`、旧 Drawer 与其它实验 Activity，且模拟入口/地图回填存在边界。推荐分两阶段：

1. **先做页面内一致性**（品牌 Header、状态卡、按钮、统一主题、折叠区），保留所有旧导航能力和深链。
2. 完成导航盘点后，再将 5 主入口升级为底部导航；旧功能归档进“高级工具”，不删除可访问路径；测试 Android 返回、旋转恢复、多窗口、无障碍与窄屏适配。

### 首页（普通用户优先）

从上到下：
1. 顶栏：候选星座标志 + 天外天；右侧设置入口（没有实际资产前沿用临时图标）。
2. **目标地点卡**：城市/地址（无法反解时显示“自定义坐标”）、纬度、经度、坐标系，显示“当前设置的目标”而不是“系统真实位置”。
3. **模拟状态卡**：未启动 / 启动中 / 运行中 / 停止中 / 状态未知；把请求成功与第三方采纳状态分开。
4. 唯一的主操作区域：启动模拟（或停止模拟），旁边“地图选点”。防止首页和地图出现两个互相误解的动作。
5. 地点捷径：最近、收藏、热门地点；首次打开、无历史时要有空状态。
6. 折叠“设备与高级工具”：Shizuku、权限、GMS、诊断等；仅状态摘要，不在首页主动索权或请求 fresh location。

### 地图页（选点任务优先）

- 地图保持主视觉，顶端单行搜索，底部显示地点和坐标的操作面板。
- 操作区明确区分“填入首页（不启动）”与“模拟这里（会启动）”，不得混淆。
- 路线/漫游/导入/回放移到折叠二级面板；地图放大缩小、定位按钮不遮挡目标面板。
- 原有坐标系转换、相机恢复、轨迹和 GPS 逻辑不可变。
- OpenFreeMap/MapLibre 底图不强制套深色滤镜；须评估瓦片本身的标签可读性。

### 诊断页（只读证据优先）

- 页面主标题“诊断中心”，首屏显示只读的当前环境摘要。
- 核心入口：快速检查 / Consumer Matrix / 被动快照；其余分组折叠保留。
- 明确“上一次成功”、“本次已确认”、“只提交请求”、“缓存读数”、“未知”，严禁 UI 文案把 Task 成功写成“微信已兼容”。
- 被动快照首次进入不能触发 getCurrentLocation 或 requestLocationUpdates；维持既有实验纯度。
- 分享/导出日志前预览隐私摘要，默认不含可识别坐标等敏感信息。
- 不给腾讯 SDK/GMS 尚未验证的路径点亮已完成状态。

### 地点页与设置页

- 地点页：保留国家国旗、A–Z 快速滑动、搜索、收藏与历史；搜索结果与地名一处显示，不再在多个页重复造入口。
- 设置页：普通设置置顶，Shizuku/实验开关/原始调试参数放“高级”下。
- 隐私、GPL 开源声明与上游署名不得在改名时被删除；用户协议中的既有陈述应逐条审查而不是仅替换品牌文字。

## 7. 严格禁止的本轮改动

- 禁止修改 `ServiceGo` 的 mock 路径、推送频率、清理时序。
- 禁止修改实验判定、微信/腾讯/GMS 的成功语义或被动读取行为。
- 禁止更改包名、签名、用户数据结构及强制清除缓存。
- 禁止自称“已兼容微信”、已注册商标、已完成实机验收。
- 禁止擅自删掉旧 Drawer 等仍承载功能的入口。
- 禁止引入需要收费的图库/设计 API/新 SDK。

本规范目的：**先统一视觉语言，再渐进式真正改界面；研究成果与功能行为不因美术升级倒退。**
