# GoGoGo VPN 已同步位置锁定（2026-10-11）

## 需求

用户担心 VPN 中断后出现自动定位回落、节点恢复后又飘到另一座城市。之前 VPN 同步模式本来就会在 VPN 网络丢失/HTTP 失败时保持现有 ServiceGo 模拟位置，但恢复联网或换节点后的成功检查仍会再次跟随 IP 城市；并且用户重开首页时可能误用默认坐标。

## 本轮行为

- 首页 VPN 卡片新增「🔒 锁定上次成功同步的 VPN 定位」「🔓 解除锁定」。
- 锁定的必要条件：**本应用主动开启过 VPN 跟随、最新坐标已成功被 ServiceGo 应用、经纬度合法且对应国家非空**；尚未成功同步不能凭空锁定，也不能锁定超时/失败/历史已被手动设置覆盖的同步结果。
- 成功锁定时，使用 SharedPreferences `commit()` 原子保存锁定的经纬度、国家城市、锁定时刻、锁定标记；同时禁用 `enabled` 跟随开关。业务回调在更新位置前再次检查 `enabled && !locked`，因此未完成的旧网络请求也不能越过锁定。
- 当前已模拟的位置保持不变；不会再因 VPN 掉线、恢复、出口切换或轮询更新坐标。ServiceGo 的已有 Provider / GMS 发布管线继续工作，不新增第二套注入。
- 模拟服务终止后，锁定标记和目标坐标仍保存在本应用私有存储。用户下次打开 GoGoGo 并点「开始模拟」，**必须优先使用已锁定目标**，而非首页默认缅甸坐标或用户无意编辑的其它值。
- 解锁只解除锁定、关闭自动跟随；**不主动修改已有模拟位置**。需要用户再明确开启 VPN 联动才会重新跟随。
- 坐标正常来自该应用自己的 VPN 出口城市 IP 地理库；仅是近似城市位置，不能保证微信接受其定位。锁定不会让 VPN 保持连接，也不会在 Android 取消/杀死 mock 服务后强制系统维持 mock：如 ServiceGo 不再运行，系统定位可能回到实际位置；这是权限和 Android 服务生命周期限制。

## 验收测试

1. 无成功同步时锁定失败，不改变坐标。
2. VPN 正常且同步成功，锁定后切换 VPN 国家、断开并恢复，已锁定坐标不变。
3. 锁定后关掉模拟服务并重新点开始，仍使用锁定坐标；重启应用也如此。
4. 锁定时不能通过普通跟随按钮意外重开同步，待处理的 HTTP callback 不能穿透锁。
5. 解锁后不改变坐标；必须手动点开启才能继续跟随。
6. 旧的手动选点、路线、漫游、回放及微信 A/B 自动诊断功能仍可工作。
7. 真实手机如果系统杀死前台服务，报告准确提示当前 mock 不保证持续（锁定配置≠阻止真实系统回退）。
