# GoGoGo Lab 39 — 首页减负与坐标输入边界

## 已复核的用户体验问题

Lab 38 已把“实验与诊断”中心的 14 个入口整理为两个常用工具 + 12 个高级入口，但日常首页 SimpleMockActivity 还保留了第二块**常驻的“状态与设置”卡片**，包含“刷新自检”“系统设置”“详细自检”。虽然详细文字默认隐藏，`onCreate` 仍无条件执行整套 `refreshDiagnostics()`：读取 GPS/NETWORK/FUSED 缓存信息及异步 GMS 最近定位回调（属于较重的系统环境探测）。

另外，首页固定模拟位置启动入口使用 Double.parseDouble + 范围比较，但 `NaN` 与任何数值比较均为 false，可能绕过坐标范围检测并传入 ServiceGo。

## 本轮改动

- 首页保持 **坐标输入 → 启动/停止 → 地图与实验中心** 的主路径；将原有“状态与设置”内容放入一个默认收起的“设备设置与自检”入口，不删原工具菜单、Wi-Fi 环境检查、腾讯环境查看、IP 读取、VPN 设置、系统设置。
- 不再因打开首页而自动调用深度 `refreshDiagnostics()`。首次**主动展开**工具区域才读取详细环境；展开后的刷新按钮和 IP/Wi-Fi 等原功能仍在，起停后只在展开时安排更新；收起时跳过预定的重读。
- 用户主动展开的状态随屏幕旋转保存和恢复。返回普通首页时的 ServiceGo RUNNING/STOPPED 标记继续刷新，但并不代表外部消费者已使用模拟位置。
- 新增无 Android 依赖的 `LabHomeCoordinates.parse`，用于**真正提交给模拟服务**的坐标以及“从首页打开地图”的初始坐标。这两个入口现在共享 WGS-84 经度 [-180,180]、纬度 [-90,90] 和 Double.isFinite 检查；`NaN`、`Infinity`、无法解析的数字一律拒绝。
- 无新增 Activity、无新的 Shizuku 调用，也不修改地图提供者、ServiceGo 注入算法或第三方 SDK 行为。
- 旧首页在 App 首次打开时申请 Android 定位权限的既有行为保持不变；此次**延迟的是详细诊断读取，而不是所有的权限弹窗**。

## 自动化测试

新建 `LabHomeCoordinatesTest` 10 个测试，包括：正常坐标、空格和负数、经纬边界、越界、NaN 经度、NaN 纬度、Infinity/溢出、缺失输入及逗号小数。UI 构建通过 Gradle/Lint 验证；折叠体验必须由实机触摸检查。

## Android 手机真机验收

- [ ] 打开首页，只出现“坐标与模拟”“地图选点与路线”“实验与诊断”和一个“展开设备设置与自检”按钮。初次显示不主动发起 GMS 最近位置诊断查询。
- [ ] 不展开工具时，点击开始/停止模拟，界面显示请求结果，但不安排隐形深度环境查询。
- [ ] 展开后原“刷新自检”“系统设置”“详细自检”都存在，详细自检手动展开可查看，点击系统设置仍弹出原 10 项工具。
- [ ] 收起→再展开不重复执行首次探测；点击“刷新自检”可主动刷新。
- [ ] 旋转屏幕后保持“设备设置与自检”展开状态；带较大系统字体时控件不重叠。
- [ ] 启动时输入 NaN（或 Infinity/越界）应看到“不是有效数字/超出范围”提示，不能启动模拟。
- [ ] 打开地图时输入合法坐标可传递给地图视口；非法坐标仍由地图按原设计使用默认参考位置，而不启动模拟。
- [ ] 系统定位关闭、模拟位置 AppOps 缺失、Shizuku 不可用时，本轮没有增加权限绕过或静默系统配置操作。
- [ ] 微信与第三方 GMS 消费者实际效果另行实测，不把通过 CI 或 home 状态提示当作兼容性证据。

版本 `2.4.0-lab39`，versionCode `2400044`；ARM64 Preview 安装包沿用公开测试签名 `com.soozooq.gogogo.test`，不能视为正式发行。
