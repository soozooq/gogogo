# 一次复制日志，不必逐项实验

2026-10-23，候选版本 `2.4.31-simple-support` / `2400099`，继续 PR #59。

用户反馈实验太多、不知道怎么操作。此前诊断首页虽有分类折叠，仍展示“先做这两项”、主动对照和定时复制等并行入口，状态提示又引导去 Consumer Matrix；统一日志主要依赖已保存记录，用户容易以为必须先逐项运行实验。

现在的日常流程：照常选点和使用微信等应用；遇到问题后，回到底部「诊断」，点「一键复制完整日志」，直接粘贴到对话。不需要选实验、填写表格、安排倒计时、做 A/B 或逐个复制。

## 默认界面

- 一个主要动作：一键复制完整日志。当前基础状态自动读取，没有必须先点的刷新或快检。
- 其他检查、应用运行、定时复制和旧研究页面保留在「高级工具（通常不用）」里，默认关闭，首次主动展开才创建这些控件。保留原有记录，不删除数据。
- 普通状态提示不再要求去 Consumer Matrix。权限缺失仍给出对应设置建议，但不会阻止导出日志，也不会自动申请权限。

## 自动汇总

复制时在工作线程读取 GPS／NETWORK 的已有缓存，以及最多等待两秒的 GMS lastLocation；记录样本年龄、模拟标记和到模拟目标的距离分类，不保存真实位置坐标。另读取本应用可见的网络承载、VPN／无线状态，附上当前版本、目标、服务生命周期和已保存的跨应用、自动任务及应用运行记录。没有旧记录时明确标记无记录，不要求补做。

当前快照标注为“复制时刻”，不能当作微信页面当时的定位来源。各缓存按自身时间读取，不声称原子同步。历史记录保留原有时间和来源，不重跑、不过期变新，也不自动判定微信成功。报告大小有上限，超出时明确截断较后的历史记录，优先保留当前状态。

复制不会主动请求新定位、订阅位置、启动／停止模拟、修改 VPN、申请 Shizuku、清理微信数据或自动上传。整理在后台线程完成；离开页面时不往后台剪贴板写入，返回后可点击复制已整理结果；页面销毁会取消整理。系统调用若较慢，只影响此次整理，不阻塞定位界面操作。

## 范围

用户已报告微信发送位置与实时共享都未采用模拟位置：关闭 VPN 很快显示真实位置，开启 VPN 找不到位置。当前 APK 版本及同窗口系统读数未提供，具体原因未知，失败结果保留在 PR #59。本次只降低反馈操作负担，保留 2.4.30 的定位引擎，不把简化界面或构建成功写成微信、无线抖音或海外定位已成功。
