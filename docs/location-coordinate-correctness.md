# 海外移动坐标与回放校验

2026-10-23，候选版本 `2.4.28-location-validation` / `2400096`。基于已合并的 2.4.27（main `0762f604`）继续实际定位开发，不恢复已结束的 PR #58，不要求用户先提交实验记录。

## 改动

- 随机移动的旧平面偏移算法在接近南北极时可能生成超出 ±90° 的纬度，导致发布门闩拒绝位置。改用球面目的点计算，覆盖两极和日界线附近；随机半径及速度设置保持原含义。
- 球面距离将舍入产生的 haversine 值限制在 [0, 1]，避免接近对跖点时算出 NaN；发布服务与回放引擎共用同一实现。
- 回放引擎自身校验点数、经纬度、海拔和时间跨度；先准备完整新轨迹，校验通过后才替换状态。拒绝新的坏轨迹时保留原播放位置、时间轴与活动状态。服务入口已有的候选回放校验继续保留，没有把它重复算作本轮新能力。
- 非有限的回放时间步长、倍率，以及路线速度、随机移动半径/速度不再污染正在使用的位置。有限参数仍沿用原来的上下限。
- 保留 2.4.27 的有效目标门闩、四通路快照、GMS 请求所有权和统一日志出口，不新增页面、定位通路或实验步骤。

## 手机使用

覆盖安装本轮 `Go_` 主程序后，按原方式选点和使用即可；无需导入 Demo。下次回传时在诊断中心一次复制日志，不逐项重跑旧实验。

## 范围

修复的是自有位置计算与会话输入。没有更改物理网络、VPN 出口、第三方应用进程或 Root 权限；不能据此宣称微信、无线抖音的实时共享或海外地点服务已兼容。

另复核了公开 VirtualApp 分支的 README 与 KNOWN-ISSUES：维护者仍声明高度不稳定，依赖 native/隐藏 API，且列出 GMS、系统版本、签名等限制，未提供本项目 vivo/微信/抖音目标组合的验收证据；不把该自述当成可直接合并的定位方案，也未复制其源码。参考：https://github.com/ISEKHON/VirtualApp 。
