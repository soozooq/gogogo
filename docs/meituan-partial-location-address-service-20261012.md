# GoGoGo · 美团地图位置成功 / 新增地址业务失败分层实验（2026-10-12）

## 用户截图（人工观察，不是第三方内部 API 证据）

截图一：美团「新增地址」页面，世界地图蓝色定位点在美国西海岸加州附近，地图瓦片能显示；页面左上角城市筛选却仍为**福州**，底部位置/收货地址列表显示「当前网络不通畅，请稍后重试」以及「重新加载」。

截图二：同一次环境美团首页位置显示**加利福尼亚州**，附近内容列表混合不同地区并标记 `>100km`，页面部分图片/页面模块能正常加载。

用户报告**开启 VPN 和关闭 VPN 两种情况下新增地址都报错**，但未记录同一时刻的 HTTP 状态码/请求域名/具体后端响应，不可直接归咎 VPN 或宣称其全部网络正常。

## 本轮研究结论的证据强弱

已观察：地图展示坐标采纳美国模拟位置；独立的首页位置标签显示加利福尼亚州；「新增地址」页城市标签仍停留国内福州；该页地址列表未正常加载。

仍未知：地址页 POI/逆地理编码/行政区划/配送可用性哪个请求失败；是否 API 返回了业务超区错误却被页面统一显示为网络不畅；VPN/无 VPN 下的 DNS/协议/连接状态；旧城市是否来自缓存/用户手动城市；是否有账号/地区可用性限制。

官方背景支持业务区域假设，但**不能直接定位截图中的具体接口**：
- 美团技术服务合作中心部分行政区划接口明确只返回国内行政区划：https://developer.meituan.com/docs/biz/biz_dishconnect_10d1548c-3717-4681-b8d9-5b0734abb108
- 美团配送公开文档存在坐标超区、配送范围等业务错误：https://peisong.meituan.com/open/doc
- 系统被动缓存与当前 SDK 定位请求不同：https://developer.android.com/reference/android/location/LocationManager#getLastKnownLocation(java.lang.String)

## 新的可重复实验

1. 进入「实验与诊断 → 跨应用定位来源对照」，应用选择新增的**美团首页 / 新增收货地址**。
2. 不改变当前 GoGoGo 已锁定的美国坐标，也不改动 VPN、Wi-Fi、蜂窝数据开关。点「开始本轮」读取 GPS/NETWORK/GMS 最后缓存与网络/蜂窝快照。
3. 跳转美团后，先确认首页显示什么地区，再进入新增地址，分别确认蓝点、城市栏和地址列表结果；只看自动状态，不手动拖动地图，也不要提交虚构收货地址。
4. 返回 GoGoGo 自动读取 AFTER 并选择对应**美团专项结果**。如做过 VPN 开关对照，额外选择对照结果；没实际做就保持 UNKNOWN。人工备注不要填写真实地址或完整手机号码。
5. 对同一条件重复两次，明确地址错误是否持续，**不在一轮实验中同时改 VPN、移动数据、模拟目标**。
6. 若愿意做下一轮**正向对照**：保持网络条件不变，自主解锁并手动模拟一个正常支持配送的国内城市，再查看新增收货地址是否能加载。由于定位目标也变化，此次是*另起一轮*，要分别记录；结束后可重新恢复原有锁定位置。若页面正常，优先考虑海外业务地区/城市与坐标不一致；若仍报错，网络/账号/服务故障仍可能。无需删除美团数据或强停第三方 App。

## 工程变更

- 现有 `LabCrossAppLocationActivity` 增加美团 app 启动入口（`com.sankuai.meituan`）。
- `LabCrossAppEvidence` 针对美团显示不同于抖音的分类：模拟蓝点、历史国内城市栏、地址列表加载错误，不因地图图片已加载就将业务错误当成“全站断网”。
- 独立记录人工观察的 VPN 开/关比较结果，未实际观察留 UNKNOWN。不给第三方 App 注入位置、不主动读取私有 API、不可断定请求状态码。
- 新的版本 `2.4.0-lab47.12-meituan-evidence` / code `2400066`，基于上轮 PR #43（蜂窝/以太网快照）；在真实设备上仍需验收。
- 一并继承上一轮 `LabCellularEthernetSnapshot` 中对 `READ_PHONE_STATE` 的权限判定修复，使移动数据开关检查无授权时返回 UNKNOWN。

## 真机验收重点

- [ ] 选择美团后专用结果标签出现，不会误把美团当成抖音的“附近地点”。
- [ ] VPN 状态没实际对照时不自动填“开关都失败”。
- [ ] BEFORE/AFTER 仍然只读，含网络连接类型和蜂窝快照，不记录真实坐标。
- [ ] 美团首页地图/地址页状况与用户选择的报告文字一致；业务错误原因标 UNKNOWN。
- [ ] APK 打包、Lint 和 JVM 回归测试完整通过。
