# GoGoGo 全流程自动诊断任务（2026-10-11）

## 核心目标

用户要的是**一次创建、阶段联动、少量人工关卡、综合总日志**，而非一堆分散的一键检测按钮。本轮在 PR #34 的自动化任务面板上新增最上方的「全流程自动诊断 · 任务总控」，独立检测保留为补充功能。

## 流程

1. 点击「创建 / 继续全流程任务」，生成 `GOGOGO-<毫秒时间戳>` 任务号。程序自动运行既有基础快检 5 个只读步骤：定位开关/权限/AppOps、主进程服务标记、微信主应用包 stopped 状态与 vivo 分身可见性、历史 Provider/GMS 清理证据、最近已保存的消费者日志。
2. 基础检查完成后，**无需再次点按钮**，自动衔接 0/10/30/60 秒被动 GPS/NETWORK/GMS 缓存观察。报告记录计划触发、实际 elapsedTime、GMS 异步返回或未返回、样本年龄和 Mock 标志。不会申请定位权限，不会主动订阅位置，也不会记录真实坐标；缺权限会跳过并注明。
3. 自动任务完成后在 `WECHAT_UI` 阶段暂停并显示唯一需要当前操作的控件：用户打开微信「发送位置」观察**自动定位**，必要时检查朋友圈所在位置。可以输入简短匿名观察文字，也允许空白并标为 UNKNOWN。GoGoGo 不读取微信界面或私有数据。
4. 进入 `BACKGROUND_AB`，用户点击「打开微信 / 控制组自动实验」，复用既有 Lab 18/19 前台录制服务各做一轮 60 秒实验。用户切换至微信等操作仍由旧界面执行。返回全流程面板自动读取 LabAutoExperimentStore；仅当两组保存时间均晚于**本任务创建时间**才作为当轮证据。缺少时保持人工关卡，可显式跳过并标明缺口。
5. 形成 `GOGOGO_WORKFLOW_TOTAL_REPORT_V1` **综合日志**：所有小任务输出按阶段加时间和任务号拼接，含手动观察、A/B 对比、完成状态、尚未验证的微信定位成功/分身进程终止结论。复制一次即可完整提交用于分析。

## 暂停、恢复与重做

- 每个阶段和已完成阶段的总报告保存在本地 SharedPreferences。应用被杀/设备重启后重新打开面板，恢复当前阶段；需要用户点击「继续」才能重做未完成的自动阶段，**不会静默后台重新请求或假定旧定时器仍运行**。
- 自动阶段切出页面（含锁屏和外部 Activity）会取消后续 Handler 采样，并将未完成阶段明确标记 `INTERRUPTED`。重新继续则重新执行此阶段；历史被中断记录仍保留。
- 可以手动中止并归档，报告标注 `INCOMPLETE_ARCHIVE`；已完成任务下一次点击主按钮创建新的任务，不将旧结果混入本轮。
- 总日志设上限 125000 字符，超出标为 `TRUNCATED`；默认不联网、不自动上传日志、不向公开 issue 发布真实位置。
- 保留独立诊断按钮，但全流程进行时不允许另开互相干扰的基础/被动检测。

## 限制

「全程自动化」在 Android 安全权限允许的边界内。普通 Android 应用不能自动读微信 UI 内容、跨用户确定 vivo 分身进程、保证强停微信，亦不能强制保活后台位置缓存任务。本任务不会自动强停第三方 app、修改 Shizuku/系统授权、改 ServiceGo 注入、冒充微信已接受模拟位置。Lab 18/19 后台 A/B 结论是相关性对照，不是微信杀进程的证据。
