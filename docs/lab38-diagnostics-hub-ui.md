# GoGoGo Lab 38 — 诊断中心 UI 整理

## 问题与目标

原 `LabHubActivity` 在同一长页面中连续排列 14 个实验/诊断入口。日常需要的“基础快检”和“Consumer Matrix”与大量深入排障、科研工具并列，手机屏幕需要长距离滚动。此轮不新增实验 Activity，不改动 ServiceGo 或第三方地图接口，只整理现有信息架构。

## 调整

- **顶部只读状态概览**：复用 Lab 31 的 `LabQuickCheckReader.read()`，只展示系统定位、精确定位、模拟位置 AppOps 这些前提的最高优先级问题/建议。显示服务 RUNNING 仅是本进程标记，不表示微信/GMS/系统位置已成功模拟。
- **常用入口常驻**：基础快检与综合报告（Lab 31/33）及 Consumer Matrix。后者仍需人主动验证真实消费端，不自动开关模拟。
- **高级项目折叠为三个组**：恢复与兼容（5）、运动与路线（3）、系统研究（4）。原恢复取证、实验仪表盘、腾讯探针等全部保留可用，不新造同功能页面。
- **手机体验**：分类按钮至少满足现有 GoGoUi 48dp 触控尺寸，显示数量与展开状态，支持无障碍内容描述；设备旋转后保持该页面的展开状态；返回主界面/其他 Activity 后自动刷新状态概览。
- **无副作用**：打开或折叠工具页不会请求 Shizuku 权限、改变 Provider、访问网络探针、启动/停止模拟服务或覆盖位置坐标。

## 回归测试

`LabHubReadinessTest` 新增 9 个纯 Java 用例：无数据、系统定位关闭、仅粗略定位、AppOps 未授权、未知授权、系统位置未知、服务运行/停止的保守解释以及 Shizuku 可选项。验收包括完整 Gradle build、unit tests、Lint 与 APK 安装构建。

## 仍需 Android 13 真机核验

- [ ] 进入首页 → 实验与诊断，看见顶部状态和“基础快检 / Consumer Matrix”两个入口。
- [ ] 展开全部三个高级分组，确认总计原有 **12** 个高级工具入口全部还在，并能各自正常返回。
- [ ] 页面旋转后各组展开状态保持一致；后台返回刷新读数，不会启动模拟。
- [ ] 系统定位关闭、只给近似定位、开发者选项未授权、完整授权等各状态都准确显示。
- [ ] 加大系统字体，在窄屏下所有分类标题可读、点击范围易操作、报告无横向溢出。
- [ ] 继续从地图页面进行收藏、路线、固定模拟、结束模拟，确认没有受到本次导航调整影响。
- [ ] 最终验证消费者应基于设备实际返回的位置和回调，而不是只凭 Hub “前置条件无阻断项”。

## 当前限制

这只是 UI 入口与只读状态提示优化；没有完成 Android 13 真实设备现场测试，也不能证明微信或 Google Play Services 现在必然收到模拟定位。公开仓库中的测试签名不可用于生产发版。
