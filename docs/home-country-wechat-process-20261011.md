# GoGoGo 首页国家显示与微信后台状态修正（2026-10-11）

## 核心改动

- 首页坐标框下实时显示「所选国家 / 城市」。与离线预设精确匹配时，复用 157 个地点和国旗资料，提供国家、城市和「离线预设」来源提示；绝不把附近预设的国家套给任意经纬度。
- 手动输入或地图任意选点：先显示「自定义坐标 · 国家待识别」，用户可显式点击「识别自定义坐标的国家」使用安卓系统 Geocoder。该接口可能联网、可能没有后端或解析失败；不接入额外私有 Key，失败不会阻断模拟。
- 更改任一经纬度立即使旧的系统地理编码结果失效；若查询异步返回时用户已更改目标或退出页面，则不再回填旧地名。旋转恢复、地图/地点选择器回填沿用原有机制。
- Lab 47 继续以 PackageManager FLAG_STOPPED 表示当前用户主微信的 **包停用标记**；它不是后台进程生死，也不能代表 vivo 应用分身。
- 增加通过既有 Shizuku UserService 的 **用户点击后执行的只读微信进程快照**：在 shell/root 自有独立服务执行固定 `ps -A -o USER,PID,NAME`，只展示 `com.tencent.mm` 及其 `com.tencent.mm:*` 子进程行；没有发现记录、命令失败、进程表截断分别明确标识，均不误报「微信已强停」。
- 「检查微信后台进程（Shizuku 只读）」在 Lab 47 前置检查中直接链接诊断页并请求运行快照。若 Shizuku 不可用，则明确提示并保留手动应用详情/分身管理入口；不会自动强停微信。
- 不修改 ServiceGo 的正常模拟发布循环、GMS Async、Provider 注入/清理、Shizuku 系统权限或微信的数据。

## 为什么不把微信“强行停止”按钮变灰当作依据

Android `ApplicationInfo.FLAG_STOPPED` 是包状态，不是活跃进程列表；OEM 的按钮交互不等于一次已完成的进程终止确认。分身微信可能属于另一 Android 用户空间，拥有同一个包名。即使可见两个同名进程，也不能仅凭包名自动确定哪个为主号、哪个为分身。单次进程快照不证明微信 UI 是否接受虚拟定位。

## 手机验收顺序

1. 首页默认应显示「缅甸 · 妙瓦底」。通过地点选择器选择「中国 · 北京」立即更新国家；地图选任意非预设点应显示「国家待识别」，不能继续沿用北京。手动输入经纬度不应立即启动模拟。
2. 对非预设点点击国家识别；如系统地理编码可用，显示系统反查国家/城市与来源；不支持时显示不可用，不影响开始/停止。查询时快速修改经纬度，旧结果不得覆盖新坐标。
3. 实验与诊断 → 前置检查 →「刷新模拟与微信状态」查看主微信包标记与 vivo 分身 UNKNOWN。对主微信手动强停后返回刷新；无论按钮能否继续点都不宣称进程已结束。
4. 点击「检查微信后台进程（Shizuku 只读）」：未启动/未授权 Shizuku 时允许用户明确开启或授权；授权后显示微信进程行或不可用原因，只包含微信相关进程，不展示完整系统进程列表。对 vivo 分身，不得从进程名自动认定主/分身归属。
5. 重做常规 Consumer Matrix 与被动快照、10/30/60 秒自动复制、普通开始/停止模拟回归测试，确认没有位置请求行为变更。
