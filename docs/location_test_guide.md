# 微信小程序定位测试指南

## 问题：影梭设置了位置，但微信显示"某某路东北30米"

### 原因分析

1. **微信不用系统 GPS 定位**
   - 微信内置了腾讯定位 SDK，综合 GPS + 基站 + WiFi + IP 做融合定位
   - 即使你 mock 了系统 GPS，微信可能通过 WiFi 扫描或基站定位拿到了真实位置
   - 关闭 WiFi 可以显著提高成功率

2. **"东北30米"是什么**
   - 这是反向地理编码（Reverse Geocoding）的结果
   - 表示：你的坐标点离"某某路"这个 POI 大约 30 米，在 northeast 方向
   - 这不是一个具体的 POI，而是算法估算的描述
   - 在百度地图中搜"某某路东北30米"当然搜不到，因为它不是一个真实的地名

3. **百度地图的数据不同步**
   - 百度地图的底图渲染、POI 搜索库、反向地理编码库是三个不同的数据源
   - 底图更新了，POI 库可能没更新
   - 或者坐标点落在了两个 POI 之间的空白区域

4. **坐标系转换精度损失**
   - 影梭注入 WGS84 → 微信内部转 GCJ02 → 腾讯地图显示
   - 每一步转换都有微小误差（通常几米到几十米）

### 简单测试方法

#### 方法 1：微信小程序测试（最准确）

1. 新建一个微信小程序项目
2. 把 `wechat_location_test.js` 的内容复制到 `pages/index/index.js`
3. 页面 WXML 添加按钮：
```xml
<button bindtap="getLocation">获取微信定位坐标</button>
<button bindtap="chooseLocation">获取地址解析</button>
<text>{{locationInfo}}</text>
```
4. 在影梭启动模拟位置后，点击按钮
5. 对比微信拿到的坐标和影梭设置的坐标

**关键观察点：**
- 如果微信 WGS84 坐标和影梭设置坐标基本一致（误差 < 100 米）→ mock 成功
- 如果差距很大（几百米甚至几公里）→ 微信用了其他定位源（WiFi/基站/IP），mock 被绕过了

#### 方法 2：更简单的坐标对比

直接用微信聊天发"位置"，看地图上标记的点在哪里，和影梭设置的位置是否一致。

#### 方法 3：网页坐标拾取

1. 打开 https://api.map.baidu.com/lbsapi/getpoint/index.html
2. 在地图上找到你想定位的点，复制坐标
3. 把坐标输入影梭
4. 启动 mock 后，在微信小程序中获取坐标对比

### 关于"搜不到"的问题

#### 为什么在百度地图搜不到"某某路东北30米"？

因为这不是一个真实的地名。反向地理编码返回的格式是：
```
[最近的道路/POI] + [方向] + [距离]
```

例如："中关村大街东北30米"表示坐标点在中关村大街这条路的东北方向 30 米处。

这是一个**相对位置描述**，不是一个可搜索的 POI 名称。在百度地图搜索框中搜索这种描述当然搜不到。

#### 高德地图有这个问题吗？

也有，但表现方式不同：

| 对比项 | 百度地图 | 高德地图 | 腾讯地图 |
|-------|---------|---------|---------|
| 坐标系 | BD09 | GCJ02 | GCJ02 |
| 反向编码精度 | 一般 | 较好 | 一般 |
| 数据更新频率 | 较慢 | 较快 | 中等 |
| POI 覆盖 | 较全 | 较全 | 一般 |

高德地图和腾讯地图都使用 GCJ02 坐标系，而百度使用 BD09。如果影梭设置的是百度地图上的坐标，转换到微信（腾讯/GCJ02）会有约 100-500 米的偏移。

### 建议

1. **关闭 WiFi**（最重要）：WiFi 扫描会让微信获得真实位置
2. **使用精确坐标**：在影梭中直接输入坐标而不是点击地图（地图点击有精度误差）
3. **选择明确的 POI 点**：不要选道路中间或空地，选择建筑物、商场等有明确 POI 的点
4. **坐标系注意**：如果要在微信中精确定位，建议在高德地图或腾讯地图上拾取 GCJ02 坐标，然后用影梭的"直接输入坐标"功能，选择坐标类型为 GCJ02
