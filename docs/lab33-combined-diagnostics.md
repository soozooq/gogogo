# GoGoGo Lab 33 — 一键综合排障报告

## 本轮要解决的问题

之前的 Lab 31（权限与定位前置条件）和 Lab 32（异常退出、Provider/GMS 历史取证）分别能复制诊断摘要；手机出现问题时还要来回打开、拼接和对比。

Lab 33 **不再新增一个重复页面**。沿用「实验与诊断 → 一键基础快检」，直接提供：

- **查看／复制综合排障报告**：合并 Lab 31 与 Lab 32 的结构化状态，先给出下一步查验方向；完整报告在对话框内预览，复制需要显式点击。
- **保存本次排障基准**：只在用户点击后将精简报告存于应用私有 SharedPreferences；不自动抓取位置、网络环境或第三方应用数据。
- **与上次基准对比**：检测时重新读取状态；展示前后摘要差异，但「没有文本变化」不代表系统就正常。
- **重新检测**：刷新页面上的基本前置条件，不增加定位请求。
- 保留 Lab 32 / 实验仪表盘 / Consumer Matrix 的深入入口；不影响原来的地图、模拟、摇杆、历史记录或其他研究页。

## 数据源与判断范围

- Android 系统定位开关、精确/近似定位权限、Mock AppOps、本进程运行标记与 Shizuku Binder；原来 Lab 31 的只读读取逻辑现集中在 LabQuickCheckReader，避免以后两份代码漂移。
- 从本应用私有 SharedPreferences 读取 Lab 23/25 的服务生命周期、GPS/NETWORK/FUSED 清理 API 结果和最后一次 GMS 异步事件。
- 三类**下一步建议**：基础前置条件缺失/未知 → 先核对系统定位和授权；可疑中断或 PENDING / DENIED / 失败 / GMS disable 未确认 → 核对 Lab 32；其余场景 → 用 Consumer Matrix 做实时定位消费者核实。
- **即使显示「基础条件没有发现明确阻断项」也不代表微信或腾讯 SDK 已通过**。单个 GMS 成功历史回调也不等于系统或其他应用已经丢弃缓存；历史 Provider remove 返回也不是系统当前状态的证明。

## 隐私和权限约束

不采集或导出经纬度、IP、SSID、基站、设备唯一标识、原始系统日志或第三方应用内部数据。只有状态枚举、Android API 级别和自己保存的清理结果。手动复制会暂存至系统剪贴板，仍需用户决定是否分享。报告基准默认不会被上传；只有用户主动覆盖才替换先前基准。

本轮**不修改** ServiceGo 的发射频率、test-provider 注册/清理、GMS setMockMode、Shizuku 授权逻辑、mock 标记，也不会自动启动/停止模拟。

## 自动化单元测试

Lab33DiagnosticBundleTest（10 个纯 Java 用例）覆盖：系统定位关闭、只有近似定位、mock 授权 UNKNOWN、PENDING、疑似异常退出、GMS 关闭仅被请求、基础可查不等于微信通过、缺少恢复记录、隐私字段检查以及两次快照差异语义。

## Android 实机验收

- [ ] 安装 2.4.0-lab33（包名 com.soozooq.gogogo.test；相同公开测试签名），**不要因为签名不匹配卸载已有可用版本**。
- [ ] 进入实验与诊断 → 一键基础快检，查看旧的基础摘要仍能正常刷新。
- [ ] 点击「查看 / 复制综合排障报告」，确认分成「基础条件」「退出及清理历史」两段；对话框内容可滚动，复制的文本与预览一致。
- [ ] 先点「保存本次排障基准」，手动改变系统定位或模拟服务状态，再点「与上次基准对比」；确认显示真实差异，不再需要进入两个实验页面截图。
- [ ] 在强停／Shizuku 断连后重新打开，确认可以给出保守的人工核对建议，不显示「完全清理成功」。
- [ ] 测试只授予近似定位、取消模拟位置 AppOps、Shizuku 不可用等情况下的 UNKNOWN/异常提示。
- [ ] 确认该页面不会自动弹出权限请求或改变模拟服务、地图位置；Android 13 深浅主题、360dp 小屏和大字体可操作。
- [ ] 分享文本前手动检查无坐标、IP、SSID、PID、日志；绝不上传私密 Key 或个人资料。
- [ ] Lab 25/30/31/32 的真机 Provider 恢复与微信黑盒对照验收仍是独立发布门槛。
