# GoGoGo 自动化诊断任务面板 · 2026-10-11

## 目标

减少用户在 Android 13 / vivo 真机上反复截图、跨页面记录时间、混淆缓存与实时定位的负担。**自动化**指用户明确启动的应用内前台诊断流程，不是操作系统的长期后台定时任务，也不保证锁屏后的采样精度。

入口：实验与诊断 → **自动化诊断任务面板**。

## 两种任务

1. **一键只读基础排障**：依次生成基础权限报告、主进程模拟服务标记、主微信 FLAG_STOPPED 与分身可见性（皆非进程存活证据）、Provider/GMS 历史清理报告和最近已保存的 Consumer 诊断。5 步在后台工作线程收集，UI 按完成顺序显示进度。不会自动启动 ServiceGo、申请权限或刷新位置。
2. **60 秒被动缓存时序观察**：用户点击后在前台页面的 0、10、30、60 秒检查 GPS 与 NETWORK 的 `getLastKnownLocation()`，以及 GMS 的 `getLastLocation()`；只记录来源、`isMock`、fixAge、NULL/错误、实际触发时间以及 *Mock 样本* 与用户上次要求目标的距离区间。绝不记录真实坐标，也不会调用 `getCurrentLocation` 或 `requestLocationUpdates`。没有定位权限直接结束任务，**不主动申请**；GMS 异步可能延迟，结束窗口 67 秒，不晚到补写。
3. **手动入口**：既有被动快照单次补拍、普通 Consumer Matrix（明确说明属于主动定位，可能更新缓存）、既有 Shizuku 微信进程只读探针。后两者都不会由前两个自动任务暗中触发。

## 状态与证据

- 页面中直接展示任务进度与步骤结果；同一时刻只能执行一个任务。
- 点击取消、离开页面、Activity 销毁都会终止后续调度，并持久保存「取消」事实。任务完成保存最近一次报告在应用自己的 SharedPreferences，支持一键复制，未自动上传。
- 使用 elapsedRealtime 调度和记录实际触发时间。安卓后台冻结、权限变化、GMS 回调延迟都可能影响报告，不以计划时间替代事实。
- 模拟状态只是 ServiceGo 标记，FLAG_STOPPED 不代表微信后台进程是否存活，vivo 分身用户空间可能不可读。
- 静态检测与 UI 反馈不代表微信已采用目标坐标；真实第三方行为仍需微信端黑盒实测。

## 关键保持不变

ServiceGo GPS/NETWORK/FUSED/GMS 注入、Shizuku 权限获取、Provider 移除、Lab 47 preflight、历史快检/被动快照、微信客户端进程和数据都不被此功能修改。本次不新增模拟启动/停止、强停微信和跨用户权限操作。

## 测试范围

- JVM：纯 Java 快照计划、NULL/未知处理、真实位置坐标脱敏和 Mock 距离区间显示。
- CI：Build Check (Gradle / Unit Tests / Lint) + Debug Preview APK 均通过后，才允许合入。
- 真机：① 一键五步完成、复制可用；② 无位置权限时不弹申请；③ 0/10/30/60s 报告实际间隔；④ 从前台离开时取消、返回后显示上次结果；⑤ 检查被动模式没有额外订阅；⑥ 对照普通 Consumer Matrix 行为不变；⑦ 用 vivo 主号与分身分别测试不可读状态。
