# GoGoGo 首页 VPN 国家显示修复（2026-10-11）

## 问题复现
vivo 首页输入框显示 WGS-84 经度 `-121.8162185`、纬度 `38.0177934`，VPN 模块显示 `🔒 United States · Antioch-Pittsburg`，但上方「所选国家 / 城市」显示自定义坐标，用户手动点系统 Geocoder 后提示「系统无法识别国家」。VPN 已经有可用的 IP 国家/城市元数据；此前上方仅检查离线预设及 Android Geocoder，没有复用该元数据。

## 本轮处理
- 新增纯 Java 方法 `LabHomePlaceLabel.vpnLabelForCoordinates(...)`：只在用户输入坐标与保存的 VPN 目标坐标几乎完全一致（已有 `LabPlaceCoordinateMatch.same`，1e-6°）时才展示保存的国家/城市；否则无结果，严禁把旧 VPN 地区套用到其他坐标。
- 使用 ISO 英文国家名映射转简体中文，常见美国返回 `🇺🇸 美国 · Antioch-Pittsburg（VPN 出口 IP 估算，非 GPS 反查）`。不认识的国家名保持接口原名、不要猜国籍或系统真实位置。
- 首页优先匹配**已锁定的 VPN 坐标/国家**；未锁定且 VPN 跟随仍开启时可匹配上次成功应用的坐标及其国家。未开启或无有效最近成功结果时不沿用过期元数据。
- 经度纬度编辑、打开页面、VPN 同步回调完成后都会刷新国家显示；Android 系统地理编码失败不再把有证据的 VPN 国家结果覆盖为失败提示。点击「识别自定义坐标的国家」在可用已保存 VPN 元数据时即时识别、无需新发网络请求。
- 不变更 ServiceGo、VPN 模拟、锁定机制、GPS/NETWORK/GMS 参数及微信相关代码。不从 IP 位置推断真实设备位置。

## 验收
1. US 截图对应经纬度和已锁定国家 → 自动显示 `美国 · Antioch-Pittsburg`，来源标识是 VPN 出口 IP 估算。
2. 解锁并手动输入另一个不一致的经纬度 → 不得继续显示原 VPN 国家。
3. 改坐标为内置离线预设 → 仍显示原来的国家/城市离线预设。
4. 任意坐标经 Android Geocoder 识别失败时 → 可继续模拟，但不冒充识别成功。
5. 新版不增加额外网络地理定位请求，仍需真实手机确认展示及用户实际使用。
