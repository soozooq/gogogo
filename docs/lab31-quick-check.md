# GoGoGo Lab 31 — 一键基础快检（只读与隐私精简摘要）

## 为什么做这一轮

实验中心当前分别有 Lab Diagnostics、Consumer Matrix、Shizuku、Provider 清理取证。用户在安卓手机上重复翻页、抄状态，容易把「模拟授权成功」误认为「微信等第三方应用已更新位置」。Lab 31 提供一个**只读的前置条件快检**，同时保留深入诊断入口。

## 新入口

GoGoGo → 实验与诊断 → **一键基础快检**。

- 独立非导出 Activity；打开页面或点击「重新检测」时才读取状态。
- 显示 Android API 版本、系统定位开关、精确/近似定位权限、模拟位置 AppOps 授权状态、当前主进程的 ServiceGo 运行**标记**、可选的 Shizuku Binder 连通性。
- 按优先级提示用户下一步：打开系统定位、回首页检查权限、选择模拟位置应用、深入诊断或 Consumer Matrix。
- 可在明确点击后复制**隐私精简摘要**，不读坐标、SSID、IP、基站、账户、设备序列号或原始 Provider/系统日志。复制内容仍会进入系统剪贴板，需用户主动决定是否分享。
- 页面有「实验仪表盘」「Consumer Matrix」两个深入入口，避免用户重复返回上一级寻找工具。
- 不启动/停止模拟、不修改 AppOps、不操作 test provider、不启动高权限 UserService、不请求定位/Shizuku 授权，也不隐藏 mock 标记。

## 不能证明的事情

- ServiceGo.sRunning 是本进程运行标记，**不能**证实操作系统 Provider、GMS 或微信真的获得了新位置。
- AppOps.MODE_ALLOWED 只说明当前应用的模拟位置授权，**不能**证明每条目标 SDK 消费者都同意 mock。
- Shizuku Binder 未连接并不阻断标准 Android mock 测试；本轮只读探测 Binder，不请求高级权限。
- 停止/重启后的 Provider/GMS 清理结果要在原有 Lab Diagnostics 中查看。快检不根据历史摘要推断清理已完成。
- 真实 Tencent LBS Key 与微信实机黑盒验收仍然是独立发布条件。

## 纯 Java 回归测试（7）

1. 系统定位关闭优先引导用户开启。
2. 只有粗略定位权限不被误标为精确授权。
3. AppOps 未授权时给出开发者选项提示。
4. 未知状态保持「无法确认」，不能冒充允许。
5. 服务运行标记不等于第三方消费者验证。
6. Shizuku 未连接不阻止标准快检的下一步。
7. 输出不包含坐标、网络地址或进程标识字段。

## Android 13 实机验收

- [ ] 保留原有可用安装；用相同包名和签名的 Lab 31 Preview 进行覆盖安装；签名冲突时**不要卸载旧版**。
- [ ] 首页 → 实验与诊断 → 一键基础快检，确认内容无需横向滚动，大小字体/系统深浅色都可阅读。
- [ ] 系统定位关/开时快检重新检测会跟着变化。
- [ ] 应用精确定位权限/近似定位权限/无权限三种状态显示清楚。
- [ ] 开发者选项中选择/取消本应用为模拟位置应用，AppOps 状态可变；DEFAULT 只能显示无法确认。
- [ ] 模拟服务启动和停止后，运行标记变化但不显示“微信已通过”。
- [ ] Shizuku 关闭时快检依然可打开、可复制；无请求权限弹窗。
- [ ] 实验仪表盘和 Consumer Matrix 两个入口正常返回，定位服务既不因快检而启动，也不被快检停止。
- [ ] 粘贴隐私摘要核对：只含 API 版本及公开的状态枚举，不含设备型号/位置/IP/SSID 或详细系统记录。
- [ ] 仍需独立完成 Lab 25/30 的异常退出、Provider 清理和第三方应用验收；Lab 31 不是稳定发布证明。
