# 应用运行：导入一次、保存状态、统一回传

2026-10-21，版本 `2.4.26-tianwaitian-runtime` / `2400094`。按用户要求收拢复杂实验操作，并继续实现受控应用的实际使用能力。用户仍为无 Root、单手机、无电脑；本轮不以先回传旧实验结果作为继续编码的条件。

## 日常操作

1. 下载一个 `tianwaitian-phone-update` 手机更新包并解压，覆盖安装 `Go_` 开头的天外天 APK；`externalDemo-debug.apk` 留作普通文件。
2. 诊断中心直接进入“应用运行”，点“打开应用”。首次选择配套 demo 并确认，之后直接打开已导入应用。
3. 正常使用备注、计数和内容页；需要回传时点“结束并复制记录”。也可下次在“应用运行”页一次复制汇总。

不用逐项重跑 V0–V3，也不用在多个页面分别复制。旧工具全部保留在默认收起的“高级验证”，专用于排错。

## 本轮继续实现的能力

- **可信文件持久导入**：明确导入后的配套 APK 保留在本应用私有目录；下次直接重新打开，不再依赖原文件选择器 URI 的持久权限。
- **每次重新核验**：重开从固定私有源复制出只读运行副本，重新核对完整 SHA、ZIP、Manifest 和身份，之后才加载代码；存在导入记录不等于跳过验证。
- **应用状态保存**：受控应用支持备注、计数、内容页及返回；保存/恢复通过严格的四个 primitive 字段，状态与配套 APK 摘要绑定。备注原文只在本地保存，诊断仅包含长度。
- **重建恢复**：Host 保存应用会话，旋转或系统重建后重新核验已授权私有源、恢复应用状态；不会把 Bundle 中的路径或 URI 当作执行授权。
- **退出与批量记录**：退出仍释放 View/监听、独立资源和临时运行 APK，保留已导入源供日后使用；近期已结束会话与历史验证可统一导出，不把历史结果当作本轮重新通过。
- **一次下载**：配对包平铺两个同次构建 APK、`SHA256SUMS`、`build-evidence.json` 和手机说明，避免两个构建混配或 ZIP 套 ZIP。

## 安全及证据边界

执行范围仍限本次构建生成的精确哈希受控 demo，任意其他 APK 仍只能用原 V3 只读检查。没有安装 demo、替换系统组件或请求 Root。宿主和受控应用共享进程/UID/权限；独立 ClassLoader 不是独立应用沙箱。

已导入源是用户明确保留的文件，和退出时应删除的临时运行副本分别记录。升级到 demo 字节已变化的新版本时需重新导入配套文件；不沿用摘要不匹配的旧状态。高级区可移除已导入文件及保存状态。

正常销毁、重建恢复、重新打开的结果分别记录。旧点击计数或先前 PASS 不能当作本次新操作；尚未结束、恢复失败或清理失败保持 INCOMPLETE/FAIL。进程被 OS 直接杀死不会凭空生成正常清理证据，也不宣称副作用 exactly-once。

这一步推进受控应用运行及状态能力，尚不是任意第三方 APK 的虚拟包管理、微信/抖音兼容或最终定位效果。真实手机表现可由用户下次一次回传，本轮云端单测、构建和产物检查分别记录。
