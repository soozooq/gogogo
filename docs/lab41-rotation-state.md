# GoGoGo Lab 41 — 首页和 MapLibre 地图状态恢复

## 实际缺陷

Lab 40 已支持“地图选点 → 填入首页”，但这两个 Activity 都通过程序动态创建 UI。首页的经纬度 EditText 没有固定 View ID，而保存页面状态的代码只记录“设备设置与自检”折叠状态；因此 **旋转手机导致 Activity 重建后，未启动的用户输入和地图回填值会重置成默认坐标**。

地图只使用首次 Intent 里的坐标初始化选点，重建后又读原启动 Intent；这会把用户旋转前在地图上新选的位置替换成起始位置。此外地图视角、样式、跟随选项重置，导入或手动编辑的路线列表在重新创建 Activity 后消失。

## 修复内容

- **首页**：只在 Android savedInstanceState 中存两段原始经纬度输入文本、可选工具展开状态，以及本次 START/STOP 请求状态与请求时的 elapsedRealtime 时间戳。保留未写完甚至格式错误的文本，让用户回到编辑状态；不自动将文本转换成模拟坐标。
- **地图**：优先恢复旋转前用户选择的点，再考虑最初首页传入地图的启动坐标。保存并恢复地图视角（中心、缩放、朝向、倾角）、两套现有底图样式选择、跟随/朝向开关和路线编辑开关。所有恢复坐标继续通过有限且合法的 WGS-84 校验；非法保存值回退到已验证的启动点，极端镜头值不会恢复。
- **路线**：使用 Activity 范围的 AndroidX ViewModel 在内存中跨配置变更保留导入或手工编辑的路点。最多 5000 个点**不塞进 Bundle/Binder**，避免 TransactionTooLarge 风险。恢复地图视图后重新渲染路线和路点摘要。
- **回填协议不变**：“填入首页（不启动模拟）”仍是唯一将地图点填回首页的明确动作，系统返回仍不更改输入；不会因旋转自动调用 ServiceGo。
- **没有增加新的实验 Activity，不改 ServiceGo、GMS、AppOps、Shizuku、位置发布频率或第三方应用兼容路径。**

## 自动测试

`LabMapSelectionRestoreTest` 新增 6 个 JVM 用例：首次启动选择初始点、已保存选点优先、合法 (0,0)、NaN 恢复退回、越界退回、WGS-84 边界恢复；保持原 `LabHomeCoordinatesTest` 的非有限输入校验。Android 系统实际 Bundle/ViewModel 生命周期仍需真机确认。

## Android 13 设备验收

- [ ] 首页手动输入经纬度，旋转横竖屏后两段文本保持原样，包括只输入一半的文本。
- [ ] 从地图执行“填入首页（不启动模拟）”之后旋转，回填坐标仍在输入框，既不发新模拟请求也不影响已运行服务。
- [ ] 地图进入后点新位置，横竖屏切换后选点仍在新位置，不会跳回刚打开地图时的初始坐标；普通返回首页仍不提交选点。
- [ ] 地图手动缩放、旋转、倾斜后再旋转屏幕，视角尽量恢复；OpenFreeMap / Demo 切换状态正确。
- [ ] 关闭“跟随”或开启“朝向跟随”，旋转后按钮状态与实际行为一致。
- [ ] 导入一条完整 GPX/KML 或手动添加路线点后旋转，路点数量、路线和路线编辑模式还在，没有额外启动路线模拟。
- [ ] 系统因内存压力完全杀死应用进程后，**不能保证 ViewModel 内路线还在**；这是已知限制。重要路线应重新导入，不能把屏幕状态恢复误认为持久存储。
- [ ] 低内存、后台恢复、应用主题/屏幕旋转等环节不引入新闪退或地图黑屏。
- [ ] 真机定位消费者成功与否仍以真实位置回调验收；生命周期修复不意味着微信定位兼容已解决。
